# Hardware Info — prototype rationale

**Status:** Round 1 (System/Processor/Graphics/Memory) approved by maintainer
(2026-07-15). Round 2 (Battery) drafted 2026-07-18, pending maintainer UAT
sign-off — see SSO-14298.

**Before:** current-state/macos/dark/hardware_info.png
**After:** renders/hardware_info_{dark,light}.png

**Changes:**
1. Put each section body (System, Processor, Graphics, Memory) in its own elevated card (DS §2 recipe: `@cardBgElevated`, 1px `@borderColor`, radius 12, one drop shadow alpha 90 / blur 26 / offset 0,2, 8px margin). In the before, the sections were near-flat outlined boxes on a same-tone page; they now read as raised surfaces. Source: DS §2 (`dashboard_tile_wrapper.cpp:107-130`). Evidence: renders/hardware_info_dark.png.
2. Three-layer surface hierarchy (`@pageContent` base / `@cardBgElevated` cards) so the elevated cards separate from the page. Source: DS §1 (`values.ini:2,29,30`).
3. Gave each section title header anatomy — a 3px accent bar + label — instead of a plain floating heading, for cross-page layout consistency with the tile-header language. The Graphics section's accent bar uses the GPU metric token (`var(--gpuColor)`), while other sections use their respective type-appropriate accent tokens (System/Processor/Memory). Source: DS §3 (`metric_tile_base.cpp:255-307`); DS §3 accent bar rule ("accent bar takes a type-appropriate metric color, as on Dashboard tiles").
4. Typography consistency inside the key/value rows: labels 9pt/600 `@color06`, values `@color05`, with a `@borderColor` divider between rows. Source: DS §4 (`style.qss:772-815`).

**Explicitly unchanged (round 1):** sidebar; the section order (System → Processor → Graphics → Memory → Battery); every key and value copied verbatim from the capture; the full-width "Copy GPU Diagnostics" button. Battery is shown as a section title only — the capture cuts off there and no Battery rows are visible, so none were invented.

## Round 2 (SSO-14298): Battery card

**Before:** current-state/macos/{dark,light}/hardware_info_battery.png (manual capture, 2026-07-17, provided directly by the maintainer via computer-use-driven screencapture on a battery-equipped Mac — see SSO-14298 comment thread; cropped to window content bounds per `current-state/CAPTURE_NOTES.md` method).
**After:** renders/hardware_info_{dark,light}.png (to be regenerated by the implementing agent from the built app, same evidence discipline as round 1).

**Why round 1 shipped without this:** every capture available at the time (harness output, all four current-state variants) cut off the page at the Battery section header — no Battery key/value rows were visible on any platform/theme, so applying the card treatment would have required guessing row content. SSO-13735's acceptance criteria explicitly scoped Battery out for this reason. This is documented as new scope in SSO-14298, not a defect in the round-1 delivery.

**Round 2 change:** apply the identical, already-approved recipe to the Battery section — no new design decision:
1. DS §2 elevated card (`@cardBgElevated`, 1px `@borderColor`, radius 12, drop shadow alpha 90 / blur 26 / offset 0,2, 8px margin) — same recipe as System/Processor/Graphics/Memory. Implementation: add `grpBattery` to the same `cardRole="elevated"` treatment already applied to `grpSystem`/`grpProcessor`/`grpGraphics`/`grpMemory` (`hardware_info_page.ui`), and add `ui->grpBattery` to the two loops in `hardware_info_page.cpp` (`WA_StyledBackground` set + `Utilities::addDropShadow(...)` call, currently lines ~92-95) that wire up the other four cards.
2. DS §3 accent bar: no change needed — `#HardwareInfoPage #sectionHeaderAccentBattery { background-color: @batteryColor; }` (`@batteryColor = #2EC27E` in both theme `values.ini`) was already wired for the header-only round-1 delivery and is confirmed present in both new captures.
3. DS §4 typography: no change needed — the shared `#HardwareInfoPage QTableWidget::item` / row-divider QSS rules are generic across all five tables, already applied to `tblBattery`.
4. Shadow count: 4 → 5.

**Rows carried over verbatim from `hardware_info_battery.png`** (no invented values, no change to `populateBattery()` data logic — this is a styling-only change): Status, Health, Charge, Cycle Count, Current Capacity, Maximum Capacity, Design Capacity, Temperature, Voltage, Power, Time Remaining.

**Explicitly unchanged (round 2):** everything from round 1's "Explicitly unchanged" list, plus: `populateBattery()` and `addBatteryRows()` data logic (`hardware_info_page.cpp`); multi-battery naming (`tr("Battery %1")`); Fans/Storage sections below Battery (out of scope, still native `QGroupBox` titles per `work-items.md`).
