# Docker — prototype rationale (round 2)

**Status:** Round-2 prototype, pending maintainer/board approval ([SSO-14982](/SSO/issues/SSO-14982)). Supersedes the round-1 UNVERIFIED skeleton from [SSO-13723](/SSO/issues/SSO-13723) (PR #235), which was deferred with no live capture.

**Before:** `docs/design/ux-modernization/current-state/linux/{dark,light}/docker.png`, captured live in round 2 ([SSO-14981](/SSO/issues/SSO-14981), PR #292) — on a GitHub Actions Linux runner, which ships a live Docker daemon (v28.0.4) used for the runner's own containerized steps; `ToolManager::checkDocker()` connected to that real daemon. Per CAPTURE_NOTES.md's round-2 section, gotcha #5 applies: the committed capture PNG shows a stale "Dashboard" sidebar highlight — this mockup renders the correct "Docker" highlight instead of copying the capture's highlight.
**After:** renders/docker_{dark,light}.png

**Corrected vs. the round-1 placeholder — the main round-2 finding:** round-1 invented a 4-image flat `ubuntu`/`postgres`/`nginx` tree with no live source, and always showed the Start/Stop container-action buttons. The live capture shows a real, populated Images tab: 7 images grouped **In Use (1)** / **Other (6)**, all the runner's own tooling/workflow images (`ghcr.io/github/gh-aw-firewall/*`, `ghcr.io/dependabot/dependabot-updater`, etc.). `docker_page.cpp:50-51,347-351` (`on_tabWidget_currentChanged`) hides `btnStartContainer`/`btnStopContainer` unless the Containers tab (index 1) is active — round-1 always showed them; the live capture (Images tab active) confirms they're absent by default, leaving only Prune Unused + Remove Selected.

**UNVERIFIED:** the Containers and Volumes tabs' content (not visible in the Images-tab capture); the exact status-bar/daemon-check text for a stopped-daemon state (the .ui's `pageDaemonStopped` page).
