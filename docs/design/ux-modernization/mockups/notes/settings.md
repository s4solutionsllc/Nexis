**Before:** `current-state/macos/{dark,light}/settings.png` (harness, 2048×1536 @2x → 1024×768 @1x). The capture shows the top of the scrolling form: **General**, **Appearance**, and the start of **Alerts**. **Changes** (only the three approved dimensions — grouping into cards, DS §3 headers, DS §4 label/field typography; all controls, labels, values, and section order are the capture's / the `.ui`'s):

1. Each `QGroupBox` form section (`groupGeneral`, `groupAppearance`, `groupAlerts`, `groupTools`, `groupScheduledCleaning`) becomes one DS §2 elevated section card (`@cardBgElevated`, radius 12, 1px `@borderColor`, single container shadow alpha 90 / blur 26 / offset (0,2)). Source: DS §2 (`dashboard_tile_wrapper.cpp:107-130`, `utilities.h:21-32`); `.ui` section list (`settings_page.ui:41,148,214,311,358`).
2. Three-layer surface hierarchy — `@pageContent` behind the scroll, `@cardBgElevated` section cards, flat controls on top. Source: DS §1 (`values.ini:2,29,30`).
3. Every section card gets a DS §3 header: a 3px ≥18px accent bar (`@accentColor`) left of the section title (`General`, `Appearance`, …). A page-level accent-bar header ("Settings" + "Preferences and alerts" source line) sits above the scroll. Source: DS §3 (`metric_tile_base.cpp:255-307`).
4. Label/field rows follow the DS §4 scale and macOS control alignment [HIG-MACOS]: label left (9pt/600 `@color06`), control right — combos as `@cardBg` selects (Language English, Start Page Dashboard, Default Disk /dev/disk3s1s1, Color Scheme Auto, Font Inter (Recommended), Tray Icon Style Color (Default), Disk Analyzer Auto (Detect)), `%`/GB steppers for the `QSpinBox` alerts (CPU/Memory/Disk/Battery all 0 %). Boolean options render as the capture's toggle switches (green `@successColor` on, `@chartGridColor` off): "Show Dashboard system summary and status bar" and "Enable disk health alerts" on, the rest off, per the capture. Source: DS §4 (`style.qss:772-815`); `.ui` labels/values (`settings_page.ui:47-306,317-513`).

**addDropShadow comparison (plan requirement).** Settings currently applies its own drop shadow at **two** call sites — `settings_page.cpp:213` (in `init()`) and `settings_page.cpp:768` (in `refreshThemeColors()`) — each calling `Utilities::addDropShadow({…14 widgets…}, 50)`. Against the `addDropShadow(widgets, alpha, blur=15)` signature (`utilities.h:13-19`) that resolves to **alpha 50, blur 15, offset (0,2)** (the offset is hardcoded in `utilities.h:30-32`). This **drifts** from the DS §2 elevated-card recipe (**alpha 90, blur 26**, offset (0,2)) on two axes:
- **Parameters:** alpha 50 vs 90 and blur 15 vs 26 — a softer, tighter shadow than the Dashboard tile chrome the design language is extracted from.
- **Placement:** the shadow is applied to **14 individual controls** (`cmbLanguages`, `cmbDisks`, `cmbStartPage`, `cmbColorScheme`, `cmbFont`, `cmbTrayIconStyle`, the four alert spinboxes, `cmbDiskAnalyzer`, `btnManageSchedules`, `btnViewHistory`, `spnThresholdGB`), not to a container. That is the inverse of DS §7 (shadow lives on the container, never per element) and DS §2 (the shadow belongs to the elevated card). The prototype moves the shadow onto each section card and leaves the controls flat.
- **Bounding (DS §9-3):** the two call sites apply the **same** fixed 14-widget list; because a widget's effect is replaced via `setGraphicsEffect()` (not stacked), re-init or a theme switch never grows the shadow count. So the modernization target is not *fewer re-applications* but *relocating* the shadow from 14 controls to the section cards and aligning alpha/blur to 90/26.

**Destructive controls:** none on this page — the capture and `.ui` show no destructive control (the `Manage Schedules…` / `View Cleaning History` buttons are `accessibleName="primary"` → `@accentColor`; the only `danger`-role controls live inside the Manage-Schedules / Cleaning-History *dialogs*, `settings_page.cpp:624,723`, which are not part of the page). Per the craft brief, `@destructiveColor` (DS §5) is therefore **not** used here.

**Below-fold note:** the **Tools** and **Scheduled Cleaning** cards and the credit footer are not in the capture (they scroll below the fold); their controls/labels/values are `settings_page.ui`-sourced (`settings_page.ui:311-536`), not copied from live pixels. The Downloads sub-controls (`Folder:` / `Move files older than`) are shown in their `.ui` indented sub-row layout.

**Explicitly unchanged:** the macOS sidebar contents/order (matches Task 6's `processes.html` macOS sidebar — "Applications" label, "Homebrew" with badge 3, no Docker/APT/GNOME rows), here with the **Settings** row highlighted (CAPTURE_NOTES.md gotcha #5 — the harness PNG's stale "Dashboard" highlight is corrected to the real page); the section order, every control type, and all labels/values.
