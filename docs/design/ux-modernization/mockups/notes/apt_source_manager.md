# APT Source Manager — prototype rationale (round 2)

**Status:** Round-2 prototype, pending maintainer/board approval ([SSO-14982](/SSO/issues/SSO-14982)). Supersedes the round-1 UNVERIFIED skeleton from [SSO-13723](/SSO/issues/SSO-13723) (PR #235), which was deferred with no live capture.

**Before:** `docs/design/ux-modernization/current-state/linux/{dark,light}/apt_source_manager.png`, captured live in round 2 ([SSO-14981](/SSO/issues/SSO-14981), PR #292). Per CAPTURE_NOTES.md's round-2 section, gotcha #5 applies: the committed capture PNG shows a stale "Dashboard" sidebar highlight (`QStackedWidget::setCurrentWidget()`, not a real click) — this mockup renders the correct "APT Repository Manager" highlight instead of copying the capture's highlight.
**After:** renders/apt_source_manager_{dark,light}.png

**Corrected vs. the round-1 placeholder — the main round-2 finding:** round-1 derived the mockup read-only from `apt_source_manager_page.ui` and `apt_source_repository_item.ui` alone. Those files do not contain the page's "Available Updates" section — it's built programmatically in `apt_source_manager_page.cpp:49-108` (`mUpdatesSection`, inserted via `ui->verticalLayout_2->insertWidget(0, ...)`, *above* the .ui-defined repository list) and was invisible to a `.ui`-only read. The live capture shows it clearly. Round-1 also mocked the repository manager's "add source" form (input field, "Enable Source" toggle, Cancel button) as if it were the default state; `apt_source_manager_page.cpp:251-265` shows those three widgets are hidden until `btnAddAPTSourceRepository` is toggled on, and the live capture confirms the real default is collapsed (Edit / Delete / Add Repository only).

**UNVERIFIED (residual):** the Available Updates row's Version column is not legibly populated in the capture (renders blank); shown as `—` here rather than invented. The toggled-on "add repository" form state (input + Enable Source + Cancel) is not captured — `.ui`-sourced only, per `apt_source_manager_page.cpp:259-265`.

**Changes:**
1. New section (not in round-1): "Available Updates" rendered as its own DS §2 elevated card with a DS §3 accent-bar header (title "Available Updates (%1)" per `apt_source_manager_page.cpp:361`, Check Now + Refresh Health as `accessibleName="primary"` buttons per `apt_source_manager_page.cpp:75,82`), and the `treeWidgetUpdates` Source/Package/Version columns (`apt_source_manager_page.cpp:92`) as a DS-table, package row verified live: `apt` / `tar`. Source: DS §2 (`dashboard_tile_wrapper.cpp:107-130`) + DS §3 (`metric_tile_base.cpp:255-307`). Evidence: renders/apt_source_manager_dark.png (top card).
2. Rendered the `listWidgetAptSources` repository list as one elevated container card (DS §2 recipe) with flat `@cardBg` rows — a GNOME-style boxed list — replacing the per-row `Utilities::addDropShadow(this, 30, 10)` each `AptSourceRepositoryItem` currently applies. Source: DS §2 + DS §7 (container-level shadow, supersedes `apt_source_repository_item.cpp:29`); boxed-list container convention [GNOME-HIG] (sources.md). Row content (all 4 rows, including the "Ubuntu Main"/"Ubuntu Security" source lines and the `resolute`/`resolute-updates`/`resolute-backports`/`resolute-security` suite names) copied verbatim from the live capture — round-1 invented generic `noble`-suite rows with no live source. All four toggles are on in the captured state (unlike round-1's one off-state row).
3. Three-layer surface hierarchy (`@pageContent` / `@cardBgElevated` container / `@cardBg` rows). Source: DS §1 (`values.ini:2,29,30`).
4. Toolbar rebuilt on header anatomy: 3px accent bar + "APT Repositories (%1)" title (count now dynamic, verified live at 4) + the `.ui`'s own "Select to delete or edit." info label (`lblAptSourceSelectInfo`) folded into the muted source line, keeping the captured Search field (`txtSearchAptSource`, placeholder "Search…"). Source: DS §3; DS §4 (`style.qss:772-815`).
5. Each repository row keeps its `.ui` structure — icon + `deb …` source line (9pt/600 title role) + source-name meta line + the enable toggle (`checkAptSource`) — unchanged as an affordance. Source: DS §4 typography; DS §7 (`style.qss:328-350`).
6. Bottom action bar rebuilt from the *default* (collapsed) state of `apt_source_manager_page.ui`'s `horizontalLayout_2`: Edit + Delete on the left, Add Repository on the right — matching the live capture exactly. Primary buttons use `@accentColor`; the `danger`-role Delete button uses `@destructiveColor`. Source: `.ui` (`apt_source_manager_page.ui` rows 200-353, accessibleName "primary"/"danger"); `apt_source_manager_page.cpp:259-265`; DS §5 status colors (`style.qss:2421-2435`).
7. Nav badge corrected: sidebar "APT Repository Manager" badge reads **1** (matching the live capture's `Available Updates (1)` count), not round-1's invented `25`.

**Explicitly unchanged:** Linux sidebar contents/order (SYSTEM section Docker → Helpers → System Logs → **APT Repository Manager** (highlighted, badge now 1) → GNOME Settings → Settings, per `app.cpp:243-270`); the Search field; the enable toggle per row; the Edit / Delete / Add Repository action set and its `.ui` order. The `.ui` also defines a "Not Found APT Repositories" empty widget (`notFoundWidget` / `lblNotFound`) for the zero-repository case — under DS §5 that would upgrade to the full icon+explanation+action empty state [NNG-EMPTY], but the prototype shows the populated boxed-list state (as captured), so it is not rendered here.

**Design Anchor constraints reflected:** the Available Updates tree uses left-aligned labels across the Source/Package/Version columns, per the Anchor's data-table convention; outlined geometric icons throughout (no filled blobs); button roles follow the Anchor's convention (Edit/Add Repository = filled accent primary, Delete = destructive red, always gated behind explicit row selection).
