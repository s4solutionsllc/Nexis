## Kiosk Mode

- [x] **FR-30: Kiosk mode UI controls and discoverability** — Kiosk mode (FR-28) is currently only accessible via keyboard shortcuts (F11 to toggle, ESC to exit). There are no buttons, menu entries, or visual hints anywhere in the UI — users must read the README or discover F11 by accident. Add mouse/touch-accessible controls so kiosk mode is discoverable and usable without a keyboard. Three sub-features:
  - **(a) System tray menu toggle** — Add a checkable "Kiosk Mode (F11)" action to the tray icon context menu, inserted before the separator/Quit action. Shows a checkmark when active. Calls `App::toggleKioskMode()`. This is especially important because once in kiosk mode the sidebar is hidden — the tray icon becomes the only non-keyboard way to exit. File: `shared/nexis/app.cpp` (`createTrayActions()`).
  - **(b) Dashboard kiosk toggle button** — Add a small fullscreen/expand icon button to the Dashboard page (top-right corner area, near the temperature/GPU sensor dropdowns). Clicking it enters kiosk mode. When in kiosk mode, the button switches to a collapse/exit icon and remains visible so the user has a clickable exit path. Consider using a bundled SVG icon (e.g. `fullscreen.svg` / `fullscreen-exit.svg`) consistent with the app's icon style. Files: `shared/nexis/Pages/Dashboard/dashboard_page.{h,cpp,ui}`.
  - **(c) Transient "ESC to exit" overlay** — When kiosk mode activates, display a semi-transparent overlay label (e.g. "Press ESC or click ✕ to exit kiosk mode") centered on the Dashboard that auto-fades after ~3–4 seconds using `QPropertyAnimation` on the label's `windowOpacity` or a `QGraphicsOpacityEffect`. Provides first-time discoverability without permanent clutter on a monitoring display. File: `shared/nexis/app.cpp` (`applyKioskMode()`).
  - **Resolved:** Added checkable "Kiosk Mode (F11)" action to tray context menu with checkmark sync. Added floating fullscreen/fullscreen-exit toggle button to Dashboard top-right corner (swaps icon on state change). Added transient "Press ESC to exit kiosk mode" overlay that holds 1.5s then fades over 2s. All three controls stay synchronized through `sigKioskToggleRequested` and `sigKioskModeChanged` signals on SignalMapper.

## Architecture Roadmap

- [ ] **FR-31: Replace GLOB_RECURSE with explicit source lists** — [Phase 2] Replace all `file(GLOB_RECURSE ...)` calls in `CMakeLists.txt` with explicit `set()` file lists. Eliminates the class of "file not found" / "stale build" issues where adding or removing a `.cpp` file doesn't trigger CMake reconfiguration. Follows CMake best practices. Architecture Review §1A.
- [x] **FR-32: QSS token validation in theme system** — [Phase 3] Add runtime validation to `AppManager::updateStylesheet()` that checks all `@tokens` in `style.qss` have corresponding values in `values.ini`, and that color values are valid hex format. Prevents BUG-21/33/36/38-class theme regressions. Architecture Review §2C. **Resolved:** Added two validation passes before token replacement: (1) regex scan of QSS for `@token` patterns with `qWarning()` for any missing from `values.ini` (excludes `@dpN` DPI tokens), (2) hex color format check on all non-`@themeName` values. Architecture Review §7 and §2C updated.
- [x] **FR-33: Testing infrastructure (Qt Test + CTest + CI)** — [Phase 4] Set up `tests/` directory, CMake test target with Qt Test framework, CTest integration, CI test step in GitHub Actions, and one smoke test to validate the pipeline. Prerequisite for FR-36. Architecture Review §3A (setup). **Resolved:** Added `Qt6::Test` to `find_package`, `BUILD_TESTING` option (default ON), `enable_testing()` + `add_subdirectory(tests)` in root CMakeLists.txt. Created `tests/CMakeLists.txt` with `nexis-tests` target. Smoke test `tests/utils/test_format_util.cpp` covers all `FormatUtil::formatBytes()` branches (7 test methods). CI test step added to `build.yml` on all 3 matrix runners. CLAUDE.md updated with test conventions.
- [x] **FR-34: Abstract base classes for platform code** — [Phase 5] Define pure virtual interfaces for the 11 Info classes and 5 Tool classes so missing platform methods are caught at compile time (not link time). Platform implementations become named subclasses (e.g., `CpuInfoLinux`, `CpuInfoMacOS`). Architecture Review §1B. **Resolved:** Converted all 10 Info classes and 4 Tool classes (ServiceTool, AptSourceTool, GnomeSettingsTool, PackageTool) to abstract base + platform subclass pattern. InfoManager and ToolManager use `std::unique_ptr` with `#ifdef Q_OS_MACOS` factory construction. PackageTool unified from divergent platform APIs into single abstract interface. ToolManager consolidated from 2 platform files to 1 shared file. 29 new platform subclass headers, 4 files removed. Zero behavior change.
- [~] **FR-35: Dependency injection for page constructors** — [Phase 6] Add constructor parameters with default values to all 14 page classes so managers can be injected for testing while production code remains unchanged. Unblocks unit testing of page-dependent logic. Depends on FR-34. Architecture Review §2B.
- [ ] **FR-36: Unit test suite (15-20 tests)** — [Phase 7] Write unit tests covering core library parsing (MemoryInfo, DiskHealthInfo, CpuInfo), utility functions (FormatUtil, FileUtil, CommandUtil), manager logic (CleanerService, ScheduleManager), and theme token validation. Targets highest-risk areas identified by past bugs. Depends on FR-33 + FR-35. Architecture Review §3A (implementation).
- [~] **FR-37: Centralized DataRefreshService** — [Phase 8] Replace ~25 per-page QTimers with a single `DataRefreshService` singleton that polls at defined intervals (1s/5s/30s) and emits typed data-change signals. Pages become reactive subscribers. Adds pause/resume for battery optimization when minimized. Depends on FR-36. Architecture Review §2A.
