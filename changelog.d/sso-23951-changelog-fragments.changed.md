Contributor workflow (SSO-23951): user-visible changes now add a fragment file under `changelog.d/` instead of editing the shared `## [Unreleased]` block in `CHANGELOG.md`, and the derivable counters in `docs/APPLICATION_OVERVIEW.md` (version, source/test LOC, file counts, test-executable and test-method counts, translation count) are generated by `scripts/gen_doc_stats.py` instead of being hand-incremented by every PR. Both were single-line regions that every concurrent PR was required to edit, so the first merge in a batch left every other open PR conflicting for no substantive reason — 6 PRs were simultaneously CI-green and unmergeable when this was filed. No user-facing behavior change; `CHANGELOG.md` is still assembled into the same Keep a Changelog format at release cut.
