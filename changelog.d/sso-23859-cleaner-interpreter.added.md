Cleaner action interpreter + sandboxed execution engine (SSO-23859, Deep Cleaning Engine epic SSO-15366): `CleanerActionInterpreter` (`shared/nexis/Managers/cleaner_action_interpreter.h`) executes a parsed `Cleaner`'s selected-option actions as a `TrustSafetyActionProvider` (SSO-15380), so dry-run preview, live confirm, and cancel come from the existing `TrustSafetyPreviewDialog`/`TrustSafetyRunner` with no new confirmation dialog. `delete`/`glob`/`walk`/`regex`/`truncate` resolve through `SandboxedPathResolver` (SSO-23859's earlier PR #407) and are confined to the caller-supplied home/cache roots; only the generic `$$home$$`/`$$cache$$` CleanerML variables are expanded, and any action whose path still contains an app-specific token (e.g. `$$profile$$`, browser-profile discovery — SSO-23860 scope) is dropped at scan time rather than guessed at. `sqlite.vacuum` opens the target database and runs `VACUUM`, estimating reclaimable bytes up front via `PRAGMA freelist_count`/`page_size` — the landed CleanerML `Action` model carries no per-row/table delete predicate for this command, so row/table deletion (e.g. cookie rows) is out of scope here and deferred to SSO-23860's browser-specific surgical deletion.
