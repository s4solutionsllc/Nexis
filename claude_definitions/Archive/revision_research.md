## 1. Project Architecture

### Directory Layout

```
Nexis/
  .github/             CI/CD workflows, issue templates, funding
  build/               Local build output (gitignored)
  icons/               Linux hicolor icon set (16px-256px, nexis.png)
  linux/
    nexis-core/        Linux platform core implementations
    nexis/             Linux platform UI implementations
    applications/      nexis.desktop
    debian/            Debian packaging (control, copyright, changelog)
  macos/
    nexis-core/        macOS platform core implementations
    nexis/             macOS platform UI implementations
    nexis.icns         macOS app icon
  output/              STALE BUILD ARTIFACTS (tracked in git -- see below)
  screenshots/         README screenshots (still named Stacer-2.0.1-*.png)
  shared/
    cmake/             CXXBasics cmake module (third-party, UNLICENSE)
    nexis-core/        Shared core library (system info, utilities, tools)
    nexis/             Shared GUI code (pages, widgets, managers, resources, themes)
    translations/      26 .ts translation files
  CMakeLists.txt       Single root build file (monolithic)
```

### Design Pattern

The project uses a **shared + platform overlay** architecture:

- **Shared headers** (`.h`) define class interfaces in `shared/`
- **Platform `.cpp` files** provide implementations in `macos/` or `linux/`
- CMake merges shared and platform sources at build time based on `APPLE` detection
- Some truly cross-platform code has `.cpp` files in `shared/` as well

### Singleton Pattern

Four manager singletons coordinate the application:

| Singleton | Purpose |
|-----------|---------|
| `AppManager` | Translations, tray icon, QSS theming with `@token` placeholder substitution, live color-scheme switching (Qt 6.5+) |
| `SettingManager` | QSettings wrapper for all user preferences |
| `InfoManager` | Facade over CpuInfo, DiskInfo, MemoryInfo, NetworkInfo, SystemInfo, ProcessInfo, ThermalInfo, GpuInfo |
| `ToolManager` | Facade over ServiceTool, PackageTool, AptSourceTool, GnomeSettingsTool |

### Navigation

`App` (QMainWindow) uses a fixed-width sidebar (220px) with `QPushButton` widgets in a `QButtonGroup`. Page content is managed by `SlidingStackedWidget` (animated slide transitions, 150ms, Linear easing). Pages are looked up by their `windowTitle` property.

### Signal Bus

`SignalMapper` (singleton) acts as a global event bus with signals: `sigChangedAppTheme`, `sigUninstallStarted`, `sigUninstallFinished`.

### Threading

Background work uses `QtConcurrent::run` with signal-based result marshaling. `App::closeEvent` waits for `QThreadPool::globalInstance()->waitForDone()`.

## 3. Core Library (nexis-core)

### Class Hierarchy

```
QObject
  +-- ProcessInfo        (only QObject subclass in nexis-core)

Plain classes (no inheritance):
  CpuInfo, DiskInfo, GpuInfo, MemoryInfo, NetworkInfo, SystemInfo, ThermalInfo

Data structs:
  Disk, GpuDevice, ThermalSensor, Process, Package, APTSource, Service

Static utility classes:
  CommandUtil, FileUtil, FormatUtil

Static tool classes:
  AptSourceTool, GnomeSettingsTool, PackageTool, ServiceTool
```

### File Inventory

**Shared (22 files):** Headers for all classes + shared implementations for cross-platform code (command_util, file_util, format_util, disk_info, process, package_tool_shared).

**macOS (15 files):** Platform implementations using Mach APIs, IOKit, sysctl, launchctl, Homebrew, AppleSMC, osascript sudo.

**Linux (15 files):** Platform implementations using /proc, /sys, systemctl, dpkg/apt/rpm/pacman/snap, gsettings, pkexec sudo.

### Key Cross-Platform Methods

| System | macOS Source | Linux Source |
|--------|-------------|-------------|
| CPU usage | Mach `host_processor_info` | `/proc/stat` parsing |
| Memory | `sysctl hw.memsize` + Mach `host_statistics64` | `/proc/meminfo` |
| Disk I/O | `iostat` command | `/sys/block/*/stat` |
| GPU | IOKit `IOAccelerator` PerformanceStatistics | `/sys/class/drm/card*` + vendor-specific |
| Temperature | AppleSMC via IOKit (TC0P, TC0D, TG0P keys) | `/sys/class/hwmon/hwmon*/` |
| Network | `getifaddrs()` + `AF_LINK` `if_data` | `/sys/class/net/*/statistics/` |
| Processes | `ps ax -weo ...` (no --no-headings) | `ps ax -weo ... --no-headings` |
| Services | `launchctl list/load/unload/start/stop` | `systemctl list-unit-files/enable/disable/start/stop` |
| Packages | Homebrew + native .app bundles | dpkg/apt, rpm/dnf/yum, pacman, snap, zypper |
| Sudo | `osascript` with administrator privileges | `pkexec` (PolicyKit) |

## 10. UI Rendering Inconsistencies

### Page Margin Inconsistencies

| Page | Left/Right | Top | Bottom |
|------|-----------|-----|--------|
| Dashboard | 0 | 0 | 0 |
| System Cleaner | 30 | 0 | 25 |
| Services | 30 | 0 | 25 |
| Processes | 25 | 0 | 15 |
| Resources | 30 | 0 | 25 |
| Helpers | 25 | 20 | 15 |
| Search | 20 | 0 | 15 |
| Settings | 20 | 10 | 20 |

There is no standard margin convention across pages.  "margin conventions should be 0 0 0"

### Hardcoded Font Families

Multiple `.ui` files hardcode `<family>Ubuntu</family>`. This font is not available on macOS or non-Ubuntu Linux distributions. Affected files:
- `services_page.ui` (labels)
- `service_item.ui`
- Various other `.ui` files

### Icon Initialization Inconsistency

- **macOS:** Uses bundled `QIcon(path)` directly for all icons
- **Linux:** Uses `QIcon::fromTheme(name, QIcon(fallback))` which tries the system icon theme first

This means the same page may look different on Linux depending on the installed icon theme, while macOS always uses the bundled assets.  "i want the app to always look the same.  identify which assets are already bundled and which assets need to be included to ensure that Linux and macOS look the same."

### CircleBar Theme Mismatch

`CircleBar` creates its `QChart` with a hardcoded dark background in the constructor, then listens to `sigChangedAppTheme` to update. There can be a brief flash of incorrect theme colors on page load before the theme signal fires.

## 14. Prioritized Recommendations

### Critical (fix immediately)

1. **Remove stale `output/` directory from git tracking.**
   ```bash
   git rm -r --cached output/
   ```
   This removes 261 tracked build artifacts with old "stacer" naming that bloat the repository.

2. **Fix YUM/DNF `getPackageCaches()` bug** (BUG-A). It currently calls the pacman method.

3. **Fix CircleBar potential double-delete** (BUG-B). Verify Qt6 ownership semantics for `QChartView::setChart()` and remove manual `delete mChart` if the view takes ownership.

### High Priority (code health)

4. **Consolidate platform-specific UI code.** The ~1,095 lines of duplicated code across macOS/Linux platform directories should be moved to shared implementations with platform-specific virtual methods or `#ifdef` guards for the small differences. Start with `search_page.cpp` (400 lines) and `system_cleaner_page.cpp` (380 lines).

5. **Consolidate `friendlySectionName()`.** Remove the two platform copies and have `PackageTool::friendlySectionName()` call through to the shared implementation.

6. **Fix `DiskInfo` raw pointer ownership** (BUG-C). Switch `QList<Disk*>` to `QList<Disk>` value semantics. No reason for heap allocation.

7. **Add bounds checking for `/proc/meminfo` parsing** (BUG-D).

8. **Change `quint8` to `int` for core count** (BUG-E).

9. **Replace `toLong()` with `toLongLong()`** for 64-bit values (BUG-F).

### Medium Priority (maintainability)

10. **Standardize page margins.** Pick a consistent convention (e.g., 25px left/right, 0px top, 20px bottom) and apply across all pages.

11. **Remove dead code.** Clean up unused `chartColors`, commented-out theme code, no-op `setSeriesList()`, dead `discoverPlists()`, orphaned assets in QRC.

12. **Fix typos in identifiers.** `lanuages` -> `languages`, `UNDEFIEND` -> `UNDEFINED`, `mSeletedRowModel` -> `mSelectedRowModel`.

13. **Replace magic numbers with named constants.** Define an enum for custom data roles.
